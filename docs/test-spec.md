# テスト仕様書（社内規則 Q&A）

このファイルは `scripts/TestReport.cs` がテストコードの説明（`[Spec]` 属性）から自動で作ります。直接編集せず、テストの `[Spec]` を直してください。
最新の実行結果は、`scripts/publish.ps1` を実行すると `RuleQA-latest/test-report.md` に出力されます。CI では成果物 `test-report` に保存されます。

## 1. 目的と範囲

業務ロジック（`src/RuleQA.Core`）が仕様どおりに動くことを、自動テスト（xUnit）で確認します。
AI の接続先は偽の HTTP サーバーに置き換え、DB はテストごとに一時フォルダの SQLite を使うので、外部の環境がなくても同じ結果になります。
テストデータには `samples/rules` の架空の規則 8 ファイル（旧版・書式の違い・規程どうしの矛盾を含む）と、評価用の質問セット `samples/questions.json` を使います。

### 自動テストの対象外（手動で確認する項目）

| 項目 | 確認方法 |
|---|---|
| 画面の表示と操作（Blazor） | `RuleQA-latest/RuleQA.exe` を起動してブラウザで操作する |
| 実際の AI（Ollama・Gemini など）との接続 | 設定画面の「接続テスト」 |
| 配布用 zip の展開と起動 | `scripts/publish.ps1` の実行後に exe を起動する |

### 2.3 AI 連携（OpenAI 互換 API）

| T03-02 | JSON スキーマ非対応の接続先では自動で切り替える | json_schema が HTTP 400 で拒否されたら json_object、それも拒否されたら形式の指定なしで送り直して成功する。API キーが空なら認証ヘッダーを付けない。 | 1 |
